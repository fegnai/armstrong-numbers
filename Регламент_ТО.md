# Регламент технического обслуживания
## программы «Поиск чисел Армстронга»

Регламент составлен по стандартной структуре документа ТО: паспортная часть
и общие положения, технологические карты ТО, контроль качества и отчетность.

### 1. Паспортная часть и общие положения

**Назначение документа.** Регламент определяет состав, периодичность и порядок
выполнения работ по техническому обслуживанию программы. Цели внедрения —
свести к минимуму простои программы, не допустить потери реестра найденных
чисел и обеспечить одинаковое качество обслуживания при каждом запуске.

**Область применения.** Правила распространяются на программу «Поиск чисел
Армстронга» (файлы main.py, backup.py, tests.py), её данные (реестр
registry.txt, папка копий backup) и рабочее место обслуживания: компьютер под
управлением Windows или Linux с установленным Python 3.

**Роли участников.** Техническое обслуживание и исправления в коде выполняет
автор программы — Арюткин М. С., группа ИСП-31. Приёмку выполненных работ
осуществляет руководитель практики — Шашкова В. Д. Привлечение сторонних
специалистов не предусмотрено.

### 2. Технологические карты ТО

Работы разделяются на два вида:
- **плановое (профилактическое) ТО** — работы по календарю для предупреждения
  сбоев;
- **внеплановое (инцидентное) ТО** — аварийные работы при возникновении
  ошибок или отказов программы.

#### 2.1. Плановое (профилактическое) ТО

| Операция | Периодичность | Пошаговый алгоритм | Ожидаемый результат | Инструменты | Вид ТО |
|----------|---------------|--------------------|---------------------|-------------|--------|
| Запуск автоматических тестов | Ежемесячно, а также после каждого изменения кода | 1. Открыть консоль в папке программы. 2. Выполнить `python tests.py`. 3. Сверить вывод с ожидаемым | Сообщение «Все тесты пройдены!» | Python 3, tests.py | Плановое |
| Контрольный поиск чисел | Ежемесячно | 1. Выполнить `python main.py`. 2. Пункт 1 меню, граница N = 1000. 3. Сверить результат | Найдено 13 чисел (последние — 370, 371, 407), запись добавлена в реестр | Python 3 | Плановое |
| Резервное копирование реестра | Еженедельно и после важных поисков | 1. Выполнить `python main.py`. 2. Пункт 4 меню. 3. Проверить папку backup | Новый файл копии `registry_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.txt` в папке backup | Python 3, папка backup | Плановое |
| Проверка размера папки проекта | Ежемесячно | 1. Открыть свойства папки программы. 2. Сравнить размер с обычным (до 1 МБ). 3. Старые копии из backup перенести на флешку | Размер папки не превышает 1 МБ, лишние копии удалены | Проводник (файловый менеджер) | Плановое |
| Проверка версии Python | Ежегодно | 1. Выполнить `python --version`. 2. Убедиться, что установлена поддерживаемая версия 3.x | Программа работает на текущей версии Python 3 | Python 3 | Плановое |

#### 2.2. Внеплановое (инцидентное) ТО

| Операция | Периодичность | Пошаговый алгоритм | Ожидаемый результат | Инструменты | Вид ТО |
|----------|---------------|--------------------|---------------------|-------------|--------|
| Восстановление реестра после сбоя | По факту отказа: registry.txt повреждён или удалён | 1. Выполнить `python main.py`. 2. Пункт 5 меню — восстановить из копии. 3. Проверить реестр пунктом 3 | Реестр восстановлен из последней копии папки backup | Python 3, папка backup | Внеплановое |
| Ошибка «файл input.txt не найден» | По факту инцидента | 1. Убедиться, что input.txt лежит в папке программы. 2. Вернуть файл или воспользоваться пунктом 1 меню. 3. Повторить пункт 2 | Файловый поиск выполняется без ошибки | Проводник, Python 3 | Внеплановое |
| Программа не запускается | По факту отказа | 1. Выполнить `python --version`. 2. Переустановить Python 3 при необходимости. 3. Повторно запустить тесты `python tests.py` | Программа запускается, все тесты проходят | Python 3, tests.py | Внеплановое |

Папку backup удалять нельзя: она единственное место хранения копий реестра.
Старые копии при нехватке места переносятся на другой носитель (флешку,
внешний диск), но не уничтожаются.
